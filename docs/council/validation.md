The raw fixture changes an in-memory queue to a SQLite spool. Its README describes
the workload, local installation constraints, current-state reconstruction, remote

The [preserved readout and focused fidelity result](notification-pilot.md) record
the actual outcome. Raw task briefs and participant responses remain in
`/tmp/council-forward-3w06cgcl/council-record.json`, with the compact execution
record in that directory's `execution.md`.

Observed behavior:

- Three actual private reviewers used Sol (reliability), Sonnet through Copilot
  (performance), and Astra (operations/modifiability). This provided two model
  families, honestly disclosed, and distinct assigned emphases.
- Participants checked the fixed baseline/target, inspected all four fixture
  files, and raised agenda amendments. Two local unit tests passed, and tracked
  implementation files remained unchanged.
- A concrete thread-affinity defect claim was challenged because the fixture
  supplied no violating caller. Its author retracted the defect label and a
  premature fix prescription in response to that argument. The author also
  accepted that failed-head blocking existed in the baseline, while persistence
  changes its lifetime. These were actual cross-participant responses.
- The readout distinguished persistence mechanisms from proven crash guarantees,
  preserved the existing ADR, and withheld an unconditional keep/revert conclusion
  pending required transition/recovery semantics and responsiveness targets.
- No questions interrupted internal deliberation; necessary user questions were
  presented as part of the final conditional readout. No ADR was written merely
  to fill the missing requirement.

Failures and limitations:

- The moderator's eight-minute deadline was 14:57:48 UTC. The next observed clock
  check after a discussion dispatch was 15:00:08, so the moderator had failed to
  check the deadline before that dispatch. Reporting then continued. The original
  trial is not a completed eight-minute council and omitted reply-back and final
  fidelity checks at its cutoff.
- The performance reviewer supplied benchmark numbers whose command/artifact
  provenance could not be reconstructed in continuation. It withdrew them as
  support; the readout did not use those numbers as established evidence.
- An initial local test run used default temporary paths outside the fixture, and
  a reviewer reported checking artifact names in `/tmp` and `/dev/shm`, outside
  the requested scope. A later run set `TMPDIR` to the fixture. Bytecode was left
  untracked; no tracked implementation or main-workspace changes resulted. These
  are scope lapses, not evidence of an enforced read-only sandbox.

The skill was narrowed in response: establish caller deadlines/allowances up front,
check before dispatches/waits, reserve readout capacity, and bound supported waits
by remaining time; trace probes to commands, conditions, and actual results within
the allowed scratch scope. This adds no fixed debate-round limit.
